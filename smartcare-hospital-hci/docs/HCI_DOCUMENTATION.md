# HCI Documentation
**Objective:** reduce cognitive load, interaction time, errors and uncertainty in common hospital workflows.
**Why role-based UI:** each role has different goals, expertise and time pressure (see USER_PERSONAS.md), so navigation and dashboards differ per role (recognition over recall; only relevant items shown).
**Design process:** problem → users → personas → scenarios → task analysis → information architecture → low-fi wireframe (sidebar + content, bottom nav on mobile) → hi-fi React prototype → usability test → iteration.
**Syllabus mapping:** M1 memory/perception (status icons + text, chunked cards); M2 reaction time (emergency banner), ergonomics (44px targets); M3 Shneiderman/Norman, screen layout, disability support; M4 KLM/GOMS/STN docs; M5 emotion (queue reassurance), colors, scenarios; M6 testing and heuristic evaluation; M7 communication (Messages), security as HCI (Share Securely dialog), data visualisation (3 purposeful bar charts).
